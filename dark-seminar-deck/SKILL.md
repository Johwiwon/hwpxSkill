# dark-seminar-deck

한국어 세미나 발표자료를 정해진 다크 테크 양식으로 만든다. 원본은 HTML 한 파일(`_build/src.html`)이고, 화면을 캡처해 이미지 PDF로 내보낸다. 내용은 매번 다르지만 양식(색, 글꼴, 부품, 쪽 틀, 빌드 방식)은 고정이다.

## 산출물과 폴더

```
<덱 폴더>/
├── index.html          ← 빌드 결과(직접 고치지 않음). 브라우저로 열면 키보드로 넘겨 볼 수 있다
├── fonts/PretendardVariable.woff2
└── _build/
    ├── src.html        ← 원본. 여기만 고친다
    └── build.mjs       ← 아이콘·차트·쪽 번호를 채워 index.html 을 만든다
```

- 덱 폴더는 사용자의 자료가 있는 곳 옆에 둔다(예: `<프로젝트>/slides`). 최종 PDF는 사용자가 원하는 이름으로 자료 폴더에 둔다.
- 캡처 PNG와 중간 파일은 임시 폴더(scratchpad)에 둔다. 임시 폴더는 날짜가 바뀌면 비워질 수 있으니, 다시 만들 수 있는 것만 둔다.
- 스크립트 위치: 이 스킬의 `scripts/`. 아래에서는 `$SK` = 이 스킬 폴더.

## 작업 순서

### 1. 목적부터 확인한다
발표 목적(연구 공유 / 도입 제안 / 교육), 청중, 대략의 장 수, 원고나 기존 자료(pptx, md, pdf)가 있는지 확인한다. 기존 자료가 있으면 먼저 읽고 장별 개요를 잡는다. 목적에 따라 결론 문장의 톤이 달라진다(`references/writing-rules.md`).
사용자에게 물을 수 없는 상황(위임받은 작업 등)이면 지시문에서 목적을 읽고, 없으면 "연구 결과 공유"로 가정한 뒤 마지막 보고에 그 가정을 밝힌다.

### 2. 덱을 만든다
```bash
bash $SK/scripts/new_deck.sh <덱 폴더>
```
견본 13장이 든 덱이 생기고 바로 한 번 빌드된다. 아이콘 패키지는 `~/.cache/dark-seminar-deck` 에 한 번만 설치된다.

### 3. 장마다 부품을 골라 채운다
- `references/components.md` 의 표에서 장 내용에 맞는 부품을 고른다. 견본 슬라이드를 복사해 글만 바꾸는 것이 가장 안전하다.
- 견본 장을 고르고 순서를 정할 때는 `slides.py` 를 쓴다. 같은 번호를 두 번 쓰면 그 장이 복제된다.
  ```bash
  python3 $SK/scripts/slides.py <덱 폴더>/_build/src.html list            # 번호와 장 제목
  python3 $SK/scripts/slides.py <덱 폴더>/_build/src.html keep 1,2,4,7,7,12,13
  ```
- 표지 오른쪽 장식(`.viz`)의 파형·EN/KO 줄은 음성 주제용 견본이다. 주제가 다르면 `components.md` 의 "표지 장식 바꾸기"대로 주제에 맞는 예시로 바꾼다.
- 장 제목은 결론 한 문장, 장 번호 배지는 손으로 매긴다. 꼬리말과 `<title>` 에 발표 제목을 넣는다.
- 장 하나만을 위한 조정은 `<section class="slide s-이름">` 처럼 이름을 붙이고 CSS 맨 아래 deck-specific 절에 `.s-이름 …` 으로 적는다. 부품 클래스 자체는 고치지 않는다(다른 장이 깨진다).
- 구조용 클래스에 한 글자 이름(`.a` `.r` `.v` `.m` `.g`)을 쓰지 않는다. 색 변형 클래스와 겹친다.

### 4. 빌드하고 눈으로 확인한다
```bash
node <덱 폴더>/_build/build.mjs
SCALE=1 bash $SK/scripts/shots.sh <덱 폴더> <캡처 폴더> [바뀐 장 번호…]
```
캡처한 PNG를 직접 열어 본다. 글자가 카드 밖으로 넘치는지, 한 줄이어야 할 문구가 줄바꿈되는지, 카드 높이가 들쭉날쭉한지, 아래 꼬리말과 겹치는지 확인한다. 여러 장은 이어 붙여 한 번에 보면 빠르다. 문제가 있으면 고치고 그 장만 다시 캡처한다.

### 5. PDF로 내보낸다
```bash
SCALE=1.5 bash $SK/scripts/shots.sh <덱 폴더> <캡처 폴더>      # 번호 없이 부르면 이전 캡처를 지우고 전체를 찍는다
bash $SK/scripts/pdf.sh <캡처 폴더> <출력.pdf>                  # PDF 실제 쪽수를 세어 캡처 수와 비교한다
```
HTML을 바로 PDF로 인쇄하지 않는다. 그라데이션 글자 둘레에 선이 생긴다. 반드시 캡처 → 이미지 PDF로 만든다. `pdf.sh` 가 "확인 필요"를 내면 캡처 폴더와 장 수를 다시 본다.
일부 장만 고쳤으면 그 장만 1.5배로 다시 찍고(`shots.sh <덱> <캡처> 3 7`) PDF를 다시 묶는다.

### 6. (선택) PPTX
사용자가 PPTX를 원할 때만 만든다. PDF와 같은 화면을 한 장씩 넣고, 발표자 노트를 붙일 수 있다.
```bash
bash $SK/scripts/pptx.sh <캡처 폴더> <출력.pptx> [notes.json] [제목] [작성자]
```
`notes.json` 은 `["1쪽 노트", "2쪽 노트", …]` 형식이다. 사용자가 "이제 PDF만 고치면 된다"고 하면 이후에는 PPTX를 다시 만들지 않고, 둘이 달라졌다는 점을 마지막에 알린다.

## 고칠 때

- 고치기 전에 `src.html` 을 임시 폴더에 복사해 둔다(되돌릴 수 있게).
- 바꾼 장만 다시 캡처하고 PDF를 다시 묶는다. 장을 넣거나 빼면 장 번호 배지를 다시 매기고, 쪽 번호를 언급한 문구("5쪽 형식")도 확인한다.
- 사용자가 문구를 직접 지정하면 그대로 쓴다. 문구의 뜻이 데이터와 어긋나면 고치기 전에 먼저 알린다.
- 수정 보고에는 바뀐 장의 쪽 번호와 바뀐 문구를 적고, 화면으로 확인했는지 밝힌다.

## 문구 원칙 (요약)

자세한 내용은 `references/writing-rules.md`. 특히 아래를 지킨다.
- 장 제목은 결론 한 문장, 비유 대신 평이한 말, 한 개념에 한 용어.
- 비율에는 분모, 범위가 다른 지표에는 단위·범위, 차이는 원자료에서 계산.
- 측정하지 않은 효과는 주장하지 않고, 지어낸 예시에는 "예시" 표시.
- 첫 질문과 정리의 답을 짝 맞춘다.

## 참고 문서

- `references/components.md` — 부품 목록, 색·아이콘·차트·표 쓰는 법. 장을 설계할 때 읽는다.
- `references/writing-rules.md` — 문구 원칙. 글을 채우기 전에 읽는다.
- `references/troubleshooting.md` — 화면이 깨지거나 스크립트가 멈출 때 읽는다.

## 환경

- 크롬(헤드리스)으로 캡처한다. WSL이면 윈도 크롬을 자동으로 찾아 경로를 변환한다. 다른 위치면 `CHROME=<경로>` 로 지정한다.
- Node.js 가 필요하다(빌드, PPTX). PPTX에는 Python 3 도 쓴다.
