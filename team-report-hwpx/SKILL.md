# 팀장 최종본 보고서 양식

앞으로 작성하는 **모든 보고서는 이 양식을 따른다.** 기준은 팀장이 직접 고친
최종본 두 편(2026-09-22)이다. 이 문서에서는 다음처럼 부른다.

| 이름 | 유형 |
|---|---|
| 최종본 A | 결과 보고형(시스템 기능 구축 결과) |
| 최종본 B | 연구 보고형(모델 선정·프롬프트 연구 결과) |

> 기준 보고서 원본은 배포 저장소에 넣지 않는다. 로컬에 있으면
> `assets/reference/` 에 두고 `make_base.py` 로 기본 양식을 다시 만들 때만 쓴다.
> 생성·점검은 원본 없이 동작한다.

> **우선순위**: 글꼴·크기·자간·간격·표 모양은 이 스킬이 최우선이다.
> `korean-report-format`(구성·흐름)과 `hwpx`(파일 조작)의 규칙이 이 문서와
> 다르면 이 문서를 따른다. 사용자가 다르게 지시하면 지시를 따르고, 이
> 문서에 반영할지는 작업이 끝난 뒤 한 줄로 제안한다.

## 1. 작업 순서

```
[1] 내용 설계        korean-report-format 스킬로 절 구성·문제점↔추진내용 대응을 잡는다
[2] 입력 텍스트 작성  references/input-format.md 문법(□ ㅇ - * < > | [표] [그림] [붙임])
[3] 생성            python3 scripts/build_report.py 입력.txt 출력.hwpx
[4] 양식 점검        python3 scripts/inspect_report.py 출력.hwpx
[5] 배포 전 검사      hwpx 스킬: validate.py --layout, fill_hwpx.py check --strict
[6] 보고            생성기의 「줄 맞춤 보고」 중 '확인' 항목을 사용자에게 전달
```

- 생성기는 팀장 최종본의 `header.xml`을 그대로 쓰는 `assets/base.hwpx`를
  복제하므로 글꼴 정의·용지·쪽번호·제목 상자가 최종본과 같다.
- **기존 HWPX를 고칠 때**는 생성기를 쓰지 않고 hwpx 스킬로 해당 문단만
  고친다. 고친 글자는 빨간색으로 남기는 사용자 규칙을 따른다. 고친 뒤
  `inspect_report.py`로 양식을 확인한다.
- hwpx 스킬 검사 도구는 `lxml`·`python-hwpx` 가 필요하다. 시스템 Python에
  없으면(외부 관리 환경) 임시 폴더에 설치해 쓴다:
  `pip install --target <작업폴더>/pylib lxml python-hwpx` 후 `PYTHONPATH=<작업폴더>/pylib`.
- 예시 입력: `examples/sample.txt` (입력 문법 전체를 쓰는 가상의 보고서).
  로컬에는 최종본 두 편을 옮긴 내부 예시가 더 있을 수 있다.

## 2. 문서 틀

```
┌───────────────────────────────────────────┐  ← 파란 띠(#0080C0)
│      보고서 제목 (HY헤드라인M 20pt 장평 90)      │
└───────────────────────────────────────────┘  ← 그라데이션 띠(#0080C0→#3CBFFF)
                          < ’26. 9. 22  지능화번역팀 >   ← 오른쪽 정렬
□ 개요
 ㅇ 현행 방식·배경 (한 문장)
  * 부연(대상 목록 등)
 ㅇ 무엇을 하고자 함 (한 문장)
□ 현황 및 문제점            ← 연구 보고형은 「□ 연구 과제」
 ㅇ 문제 (명사형 종결)
  - 구체 원인
□ 추진 내용
 ㅇ (라벨) 무엇을 했는가
         < 표·그림 제목 >
  [표 / 그림]
   * 표 읽는 법
  - 세부
□ 결론 및 향후 계획
 ㅇ 성과
 ㅇ 다음 행동
                 - 이하 여백 -
──────────── 새 쪽 ────────────
[붙임1│ 붙임 제목                    ]   ← 붙임 띠
 ㅇ (라벨) … 또는 바로 표
```

### 절 구성 두 가지

| 유형 | □ 절 |
|---|---|
| 결과 보고형 | 개요 → 현황 및 문제점 → 추진 내용 → 결론 및 향후 계획 → 붙임 |
| 연구 보고형 | 개요 → 연구 과제 → 추진 내용 → 결론 및 향후 계획 → 붙임 |

- 「추진 내용」「결론 및 향후 계획」은 띄어 쓴다.
- 연구 과제 절은 `ㅇ 과제 → - 세부 → * 검토 항목` 3단으로 쓰고, 절 끝에
  AS-IS/TO-BE 그림 표를 둔다(전체 폭).
- 본문 마지막에 `- 이하 여백 -`(가운데, 휴먼명조 15pt)을 둔다.

## 3. 글꼴·크기·자간 (핵심 표)

| 위치 | 머리 기호(공백 포함) | 글꼴 | 크기 | 자간 | 장평 | 문단 |
|---|---|---|---|---|---|---|
| 제목 | — | HY헤드라인M | 20pt | 0 | **90** | 가운데, 줄간격 200% |
| 작성일·부서 | `< ’26. 9. 22  지능화번역팀 >` | 함초롬돋움 | 13pt | 0 | 100 | 오른쪽 |
| □ 절 | `□ ` | HY헤드라인M | 16pt | 0 | 100 | 양쪽, 160% |
| ㅇ 항목 | `␣ㅇ␣` | 휴먼명조 | 15pt | 0 (줄 맞춤 시 −1~−16) | 100 | 양쪽, 160%, 내어쓰기 ≈ −2980 |
| ㅇ 라벨 | `(라벨)` | 휴먼명조 **굵게** | 15pt | 문장과 같게 | 100 | |
| - 항목 | `␣␣-␣` | 휴먼명조 | 15pt | 0 (줄 맞춤 시 −1~−16) | 100 | 양쪽, 160%, 내어쓰기 ≈ −2952 |
| * 주석 | `␣␣*␣` / `␣␣␣*␣` | 함초롬돋움 | 13pt (표 아래 12pt도 씀) | 0 (줄 맞춤 시 −4~−18) | 100 | 양쪽, 160% |
| ** 둘째 주석 | `␣␣**␣` | 함초롬돋움 | 13pt | | 100 | |
| 캡션 | `< 제목 >` | 함초롬돋움 | 13pt | **−7** | 100 | 가운데 |
| 표 머리행 | — | 함초롬돋움 **굵게** | 12pt (조밀한 표 11pt) | 0 | 100 | 가운데, 130% |
| 표 본문 | — | 함초롬돋움 | 12pt (조밀한 표 11pt) | 0 (넘칠 때 −1~−22) | 100 | 가운데, 130% |
| 괄호 보충 | `(1만 건)` 등 | 본문 글꼴 | 본문 −2pt (13pt) | | | |
| 붙임 번호 | `붙임1 ` | HY헤드라인M 흰색 | 16pt | 0 | 100 | 가운데 |
| 붙임 제목 | ` 제목` | HY헤드라인M | 15pt | 0 | 100 | 줄간격 200% |

- ㅇ 앞 공백 1칸, - 앞 2칸, ㅇ 바로 아래 `*` 는 2칸, `-`·표 아래 `*` 는 3칸.
- 연구 과제 3단에서는 `-` 앞을 3칸으로 써도 된다(최종본에 2칸·3칸이 섞여 있음).
- **장평은 제목만 90**, 나머지는 모두 100이다. 줄을 맞출 때 장평은 건드리지 않는다.
- 줄 맞춤 자간은 문단의 문장 런 전체에 같은 값을 준다. 머리 기호 런은 0으로 둔다.

용지·여백·테두리·셀 여백 같은 숫자는 [references/format-spec.md](references/format-spec.md).

## 4. 간격 (빈 문단)

문단 사이 간격은 **글자 크기만 다른 빈 문단**으로 만든다(1pt = 100 HWPUNIT).

| 자리 | 빈 문단 크기 | 비고 |
|---|---|---|
| 작성일 줄 뒤 / 다음 □ 앞 | 10pt | 최종본 B는 8pt |
| □ 바로 뒤 | 5pt | 일부 3pt |
| ㅇ 묶음 사이 | 3pt | 최종본 B는 5pt |
| ㅇ → 하위(-, *) / 하위끼리 | 1pt | 최종본 B는 ㅇ 뒤 2~3pt |
| 캡션 위아래 | 1pt | |
| 표·그림 앞뒤 | 3pt | |
| 붙임 띠 뒤 | 5pt | |

생성기는 위 기본값을 쓰고, 입력 첫머리 `간격: ㅇ=5, 절=8` 로 바꿀 수 있다.
**기존 문서를 고칠 때는 빈 문단 크기를 바꾸지 않는다**(쪽 배분이 무너진다).

## 5. 표·그림·캡션·주석

- **표 폭**: ㅇ 아래 표는 45350(160mm)으로, 표를 담은 문단을 오른쪽 정렬해
  표 왼쪽 끝이 `ㅇ ` 뒤 글자 시작선에 오게 한다. 붙임 띠 바로 뒤에 ㅇ 없이
  오는 표와 AS-IS/TO-BE 그림 표는 전체 폭(48180)이다.
- **선**: 0.12mm 실선(검정), 셀 여백 좌우 0.5mm·상하 0.15mm, 세로 가운데.
- **머리행 배경**: `#DAEEF3`(최종본 A). 최종본 B는 `#DFE6F7`.
  한 보고서 안에서는 한 색만 쓴다.
- **강조 행**: 선정 결과 등 한 행을 돋보이게 할 때 `#FFF7CC`(또는 `#FAF3DB`).
- **핵심 수치**: 표 안 핵심 결과만 **빨간 굵은 글씨**로 강조한다
  (예: 개선 결과 수치). 붙임의 전후 비교 예시는 틀린 곳 빨강, 고친 곳 파랑.
- **캡션**: 표·그림 위에 `< 제목 >`. 최종본 A는 캡션을 달았고, 최종본 B는 본문 문장이 표를 설명하므로 캡션 없이 썼다. 표가 무엇인지 바로
  앞 문장으로 드러나지 않을 때 단다.
- **주석**: 표 아래 `*`, 둘째는 `**`. 표를 읽는 열쇠(지표 뜻, 분류 기준)만
  쓰고 결론은 본문 `-` 에 쓴다. 같은 표의 짧은 주석 두 개는 한 줄로 합친다
  (`* 지표1: 뜻, 지표2: 뜻`). **`•` 는 쓰지 않는다.**
- **그림**: 1×1 표 안에 그림을 셀 배경(꽉 채움)으로 넣고 테두리는 점선.
  화면 캡처는 이 방식, 여러 그림을 나란히 둘 때는 표 셀마다 그림을 넣는다.

## 6. 줄 맞춤 (자간)

팀장은 줄이 어중간하게 넘어가는 문단의 **자간을 문단 단위로 좁혀** 한 줄을
줄였다(본문 −1~−16, 표 셀 −1~−22).

- 두 줄 이상인데 마지막 줄이 절반에 못 미치면 → 자간을 좁혀 한 줄 줄인다.
- 본문 −15까지 좁혀도 안 줄면 → 문장을 보강하거나 줄인다(생성기가 '확인'으로 보고).
- 표 셀은 −15까지 좁혀 한 줄에 넣고, 그래도 넘치면 줄바꿈한다. 영문 문장 셀은 좁히지 않는다.
- 최종본에도 둘째 줄이 30% 안팎인 문단이 몇 개 남아 있다. 의미를 해치면서까지
  채우지는 않는다.

`build_report.py` 는 최종본 4개 파일의 실제 줄바꿈 156건으로 맞춘 폭 모델
(153건 일치)로 이 작업을 자동으로 한다. 추정치이므로 한글에서 열어 '확인'
항목만 눈으로 본다. 자동 자간 값은 팀장 값과 1~2 차이로 비슷하다
(예: 팀장 −9 / 생성기 −9, 팀장 −15 / 생성기 −14).

## 7. 문장 쓰는 법 (팀장 수정 경향)

상세는 [references/writing-style.md](references/writing-style.md)(로컬에 `writing-style-internal.md` 가 있으면 원문 전후 비교도 함께 본다). 요지는 다음과 같다.

1. **개요는 ㅇ 두 개**: 현행 방식의 문제(또는 배경) 한 문장 + 「~하고자 함」 한 문장.
   대상 목록 같은 부연은 `*` 주석으로 내린다.
2. **명사형으로 짧게 끝낸다**: 「규격이 상이」→「규격 상이」, 「대응이 필요」→「구현 필요」,
   「점검이 곤란」→「구현 난해」, 문제 ㅇ 은 「~부재」「~난해」「~필요」로 끝낸다.
3. **핵심어를 하나로 정해 라벨에 반복**한다: (실시간 ○○ 관제)·(△△ 관제)·(□□ 관제)처럼 같은 말로 묶는다.
4. **라벨은 기능 이름으로 짧게**: (오픈소스 모델 선정)→(모델 선정), 실험 구성은 (비교 대상)·(비교 환경)·(결과)처럼 짝을 맞춘다.
5. **본문에서 괄호 속 영문 지표·약어를 뺀다**: 「정확도(F1)」→「정확도」. 지표 설명은 표 아래 `*` 로.
6. **독자에게 필요 없는 작업 경위를 지운다**: 사용 도구, 데이터 입수 경위, 본문과 겹치는 주석.
7. **표 머리말은 짝을 맞춘다**: 「점검 요청 / 정상 판정 기준」→「점검 정보 송신 / 점검 정보 수신」.
8. **결론은 ㅇ 2~3개**: 성과 하나, 다음 행동 하나를 구체적으로.
9. **붙임 제목은 내용을 직접 말한다**: 「구성 및 대응」 같은 포괄 제목 대신 「단계별 ○○ 설정 내역」처럼 무엇이 들어 있는지 쓴다.
10. ㅇ 라벨은 굵게, `-` 라벨은 굵게 하지 않는다. `-` 라벨은 한 ㅇ 아래에서 모두 붙이거나 모두 뗀다.

> 최종본에도 「향상을 위해 … 향상을」 같은 조사 중복 오타가 남아 있다.
> 문장 형태만 따르고 오타는 따라 하지 않는다.

## 8. 직전본 → 최종본에서 바뀐 서식 (다시 틀리지 말 것)

| 항목 | 직전본(우리가 쓴 것) | 최종본(팀장) |
|---|---|---|
| 표 안 글꼴 | 휴먼고딕 13pt | **함초롬돋움 12pt**(조밀 11pt) |
| 표 아래 주석 | `•` 휴먼고딕 13pt | **`*`·`**` 함초롬돋움 12~13pt** |
| 작성일 줄 | 한양중고딕 12pt | **함초롬돋움 13pt**(최종본 B 12pt) |
| 표 제목 | 없음 또는 `<제목>` 휴먼고딕 | **`< 제목 >` 함초롬돋움 13pt 자간 −7, 표 위 가운데** |
| 개요 | ㅇ 3개(배경·목적·범위) | **ㅇ 2개 + `*` 부연** |
| 연구 보고서 둘째 절 | 현황 및 개선 필요성 | **연구 과제(ㅇ - * 3단 + AS-IS/TO-BE)** |
| 붙임 | ㅇ 설명 + 표 | 표만 두어도 됨 |
| 본문 끝 | 없음 | **`- 이하 여백 -`** |
| 제목 | 길면 19pt 자간 −6 | 20pt 장평 90 유지(짧게 다듬음) |

---

## 9. 지켜야 할 것

1. **새 보고서는 생성기로 만든다.** 빈 문서에서 XML을 손으로 짜지 않는다.
2. **표 안·주석에 휴먼고딕을 쓰지 않는다.** 함초롬돋움이다.
3. **주석 기호는 `*`·`**`.** `•`·`※`를 쓰지 않는다.
4. **장평은 제목(90) 외에는 100.** 줄 맞춤은 자간으로만 한다.
5. **줄 맞춤 자간은 본문 −16, 표 −22를 넘기지 않는다.** 더 필요하면 문장을 고친다.
6. **기존 문서의 빈 문단 크기와 내어쓰기 값을 바꾸지 않는다.**
7. **배포 전 hwpx 스킬 검사를 통과시킨다**(validate --layout, fill_hwpx check --strict).
8. 생성 결과를 보고할 때 '확인' 항목(마지막 줄이 짧은 문단)을 함께 알린다.
