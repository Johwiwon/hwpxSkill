# 팀장 수정 경향 — 문장 쓰는 법

우리가 쓴 직전본(2026-09-11)과 팀장이 고친 최종본(2026-09-22)을 문단 단위로
대조해 뽑은 규칙이다. 예시는 원문이 아니라 같은 형태로 지은 가상의 문장이다.
(원문 전후 비교는 로컬 전용 `writing-style-internal.md` 에 있다. 배포 저장소에는 없다.)

---

## 1. 개요는 ㅇ 두 개 — 「현재 방식의 문제」와 「하고자 함」

```
직전  ㅇ 문서 검색 품질을 높이기 위해 본문 검색 기능을 구축
      ㅇ 문서가 여러 저장소에 흩어져 있고 검색은 제목만 대상으로 함
      ㅇ 업무 매뉴얼·회의록·보고서의 본문 검색 및 유사어 검색

최종  ㅇ 사내 문서 검색이 제목 일치 방식으로만 동작하여 본문 내용은 찾지 못하는
        비효율적인 방식 적용 중
        * 대상: 업무 매뉴얼, 회의록, 보고서
      ㅇ 본문 검색과 유사어 검색을 지원하는 기능을 구축하여 필요한 문서를 한 번에
        찾을 수 있도록 개선하고자 함
```

- 첫 ㅇ: **지금 어떻게 하고 있고 무엇이 비효율인가**(「~적용 중」, 「~필요」).
- 둘째 ㅇ: **그래서 무엇을 하려는가**(「~하고자 함」).
- 대상 목록 같은 부연은 본문에서 빼 `*` 주석으로 내린다.
- 「최근 ~이 향상됨에 따라」 같은 배경 설명은 지우고 목적과 범위만 남긴다.

## 2. 문제는 짧은 명사형, 원인은 `-` 로

```
직전  ㅇ 문서 본문 내용을 검색할 수 있는 수단이 부재
최종  ㅇ 본문 내용 검색 수단 부재

직전    - 검색 엔진마다 색인 방식이 달라 결과 형식이 상이
최종    - 엔진별 색인 방식이 달라 결과 형식 상이

직전    - 부서마다 용어가 달라 개별 대응이 필요
최종    - 부서별 용어가 달라 개별 사전 구축 필요
```

- 「~이 부재/상이/필요」에서 조사를 뗀 **명사형**(「부재」「상이」「필요」「난해」)으로 끝낸다.
- `-` 앞머리에서 ㅇ 와 겹치는 말을 지운다.
- 문제 ㅇ 은 한 줄에 들어가게 쓴다.

## 3. 추진 내용: 라벨은 기능 이름, 핵심어 반복

```
직전  ㅇ (검색 응답 개선) 서로 다른 저장소를 하나의 검색 화면으로 통합
최종  ㅇ (통합 검색 관제) 저장소별 색인 방식에 맞춰 수집 방식을 적용하여 한 화면에서
        검색 가능한 통합 검색 화면 구현
```

- 보고서의 핵심어를 하나 정해 **라벨마다 반복**하면 한 묶음으로 읽힌다
  (예: (통합 검색 관제)·(외부 문서 관제)·(색인 상태 관제)).
- ㅇ 문장은 「무엇을 구현/선정/구성」으로 끝낸다.
- 라벨은 짧게: (오픈소스 검색엔진 선정) → (검색엔진 선정).
- 실험형 `-` 라벨은 짝을 맞춘다: (비교 대상)·(비교 환경)·(결과).
- 괄호 속 보충(목록·건수)은 본문보다 2pt 작게 쓴다.

## 4. 괄호 속 영문 지표·약어는 본문에서 뺀다

```
직전  - (품질 검증) 정확도(F1)와 재현율(Recall)을 개선 전후로 비교한 결과 …
최종  - (품질 검증) 정확도와 재현율을 개선 전후로 비교한 결과, A는 두 지표 모두
        상승, B는 정확도 상승
```

- 지표 이름은 표 머리행과 표 아래 `*` 주석에만 둔다.
- 「~하였고 ~에서도 ~이 상승」을 「A는 ~ 상승, B는 ~ 상승」의 **나란한 명사형**으로 줄인다.
- 약어보다 우리말 이름을 쓴다(제목에 붙인 괄호 약어도 뺀다).

## 5. 주석: `*`·`**`, 합치고 덜어낸다

```
직전     • 지표1: 뜻
         • 지표2: 뜻
최종     * 지표1: 뜻, 지표2: 뜻

직전     • 사전: ○○로부터 제공받은 규칙 3,000건으로 …
         • 그중 본문에 맞지 않는 규칙을 제외하고 300건 선별
         • 같은 규칙을 기존·개선 결과에 모두 적용
         • 검출은 ○○ 도구로 작성한 스크립트로 수행
최종     * 사전: ○○의 규칙 3,000건 중 실험에 적합한 300건을 선별
```

- 표를 읽는 데 꼭 필요한 정의만 남긴다. 사용 도구, 입수 경위(「~로부터 제공받은」),
  당연한 설명(같은 규칙 적용), 본문 `-` 와 같은 말을 하는 주석은 지운다.
- 둘째 주석은 `**`. `•` 는 쓰지 않는다.

## 6. 표·그림

- 표·그림 위에 `< 제목 >` 캡션을 단다(앞 문장이 표를 충분히 설명하면 생략 가능).
- 표 머리말은 **짝이 맞게** 쓴다: 「요청 / 정상 판정 기준」 → 「정보 송신 / 정보 수신」,
  「확인 내용 / 판정 결과」 → 「점검 내용 / 점검 상태」.
- 설명용 그림은 그 그림을 설명하는 `-` 문장 바로 뒤에 둔다.
- 선정 결과 행은 배경색으로, 핵심 수치만 빨간 굵은 글씨로 강조한다.

## 7. 결론 및 향후 계획

- ㅇ 2~3개: 성과 하나, **다음에 할 일 하나**를 구체적으로.
- 향후 계획 아래 `-` 를 늘어놓지 않는다. 앞 절에서 말한 내용은 반복하지 않는다.
- 본문이 쪽 중간에서 끝나 빈 공간이 남으면 끝에 `- 이하 여백 -`. 쪽 아래까지 찼으면 쓰지 않는다.

## 8. 연구 보고서의 둘째 절은 「연구 과제」

- 「왜 필요한가」를 길게 쓰지 않고 **무엇을 연구했는가(과제 2~3개)**를 먼저 보인다.
- `ㅇ 과제 → - 세부 과제 → * 검토 항목(2~3개)` 3단, 절 끝에 AS-IS/TO-BE 그림 표.
- 과제 ㅇ 와 추진 내용 ㅇ 를 1:1로 대응시킨다.

## 9. 붙임

- 붙임 하나에 주제 하나. 제목이 내용을 직접 말하면 ㅇ 설명 없이 표로 시작해도 된다.
- 붙임 안에 표가 둘 이상이면 표마다 `ㅇ (라벨) 설명` 을 둔다.

> 최종본에도 조사가 겹친 오타가 남아 있었다. 문장 형태만 따르고 오타는 따라 하지 않는다.
