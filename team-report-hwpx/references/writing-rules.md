# 문장 작성 규칙

절 구성과 글꼴이 맞아도 문장이 어긋나면 보고서로 읽히지 않는다. 이 문서는
**항목 하나하나를 어떤 문장으로 쓰는가**를 다룬다.

> 출처: 실제 보고서 작업에서 받은 지적(2026-09-09~10)과 팀장 최종본(2026-09-22).
> 예시는 원문이 아니라 같은 형태로 지은 가상의 문장이다(주제: 사내 문서 검색 개선).

---

## 1. 괄호를 나열 기호로 쓰지 않는다

`A(...)에서 B(...), C(...)` 처럼 괄호 딸린 이름을 늘어놓으면 목록이지
문장이 아니다. **무엇을 어떻게 해 나갔는지 서술로 푼다.**

```
전: 1차안(제목 검색)에서 2차안(본문 색인), 최종안(유사어·정렬) 순으로
    기능을 보강

후: 제목 검색으로 출발하여 본문 색인과 유사어·정렬 기능을 차수마다 추가
```

**아래 표에 이미 나오는 이름은 본문에서 빼도 된다.** 위 예에서 「1차안 /
2차안 / 최종안」이 바로 다음 표의 첫 열이라면, 본문은 무엇을 더해 갔는지만
말하면 된다.

머리 라벨 `ㅇ (검색엔진 선정)` `- (품질 검증)` 은 나열이 아니라 항목의
이름이므로 이 규칙과 무관하다.

---

## 2. 추진내용 ㅇ 에는 `(라벨)`, `-` 라벨은 한 ㅇ 아래에서 통일한다

추진내용의 `ㅇ` 은 `(라벨)`로 시작한다. 그 아래 `-` 는 **모두 라벨을 붙이거나
모두 뗀다.** 팀장 최종본은 실험 구성처럼 나란한 항목에는 `-` 라벨을 붙였고
((비교 대상)·(비교 환경)·(결과)), ㅇ 을 풀어 쓰는 짧은 설명에는 라벨 없이 썼다.
한 ㅇ 아래에서 섞으면 읽는 사람은 라벨 없는 줄이 앞 항목의 연장인지 새
이야기인지 알 수 없다.

```
좋음:
  ㅇ (유사어 검색) 시험 검색어 100개로 3개 차수에 걸쳐 검증
    - (검증 방법) …
    - (사전 보강) …
    - (품질 검증) …

좋음:
  ㅇ (통합 검색 화면) … 한 화면에서 검색 가능한 통합 화면 구현
    - 검색어가 포함된 본문 구절을 결과에 함께 표시하여 내용을 바로 확인
    - 오래된 문서는 회색으로 표시하여 최신 문서와 구분

나쁨:
    - (품질 검증) … 두 지표가 함께 상승
    - 회의록은 재현율이 소폭 하락                    ← 라벨이 섞여 이게 뭔지 모름
```

### 라벨을 붙일 수 없으면 앞 항목에 합친다

라벨이 떠오르지 않는다는 것은 대개 **독립된 항목이 아니라 앞 항목의 단서**
라는 뜻이다. 억지로 이름을 붙이지 말고 앞 문장에 이어 붙인다.

```
- (품질 검증) 정확도와 재현율로 개선 전후를 비교한 결과 매뉴얼은 두 지표가
  함께 상승하였고 회의록은 정확도가 상승한 반면 재현율은 소폭 하락
```

합쳤을 때 세 줄을 넘으면 그때는 **라벨을 새로 지어 나눈다.** `(잔여 누락)`
`(누락 특성)` 처럼 그 항목이 다루는 대상을 이름으로 삼는다.

---

## 3. 표 하단 `*`에는 표를 읽는 데 필요한 것만 남긴다

표 아래 `*`(둘째는 `**`)는 **표를 해석하는 열쇠**다. 옛 문서의 `•` 는 `*` 로
바꾼다. 결과가 어떻다는 이야기는 표 위 `-` 본문의 몫이다.

| 표 하단에 남길 것 | 위 본문으로 올릴 것 |
|---|---|
| 열·행 이름의 뜻 (`기존`=제목 검색, `누락`=찾지 못한 문서) | 몇 건이 어떻게 개선되었는지 |
| 지표 정의 (`재현율`: 찾아야 할 문서 중 찾은 비율) | 지표가 얼마나 올랐는지 |
| 측정 범위·조건 (세 차수 모두 검색어 100개 기준) | 그래서 무엇을 확인했는지 |
| 데이터 출처·선별 기준 | 결론·판단 |

```
전:  [표]
     * 기존은 제목 검색, 개선은 본문·유사어 검색
     * 1차안 → 2차안 → 최종안 순으로 기능을 보강        ← 본문에서 할 말
     * 기능을 더할수록 두 지표가 상승하여 최종안 확정     ← 본문에서 할 말

후:  - (사전 보강) 제목 검색으로 출발하여 … 기능을 더할수록 정확도와 재현율이
       함께 상승하여 최종안을 운영 기능으로 확정
     [표]
     * 기존은 제목 검색, 개선은 본문·유사어 검색으로 세 차수 모두 검색어 100개 기준
```

**표에 있는 열인데 뜻을 짐작하기 어려우면 설명을 새로 쓴다.** 낯선 말이 열
이름으로 들어가 있으면 하단에 한 줄 붙인다.

## 4. 형제 항목끼리 같은 사실을 두 번 말하지 않는다

`flow.md` 의 「절 사이 중복은 정상」과 혼동하면 안 된다.

| 관계 | 중복 | 판단 |
|---|---|---|
| 개요 ↔ 현황 ↔ 추진내용 (**절 사이**) | 같은 사안을 층위를 달리해 반복 | **정상** |
| `- (누락 감소)` ↔ `- (누락 특성)` (**형제 항목**) | 같은 숫자·사실을 두 번 짚음 | **합친다** |

같은 숫자가 형제 항목 두 곳에 나오면 신호다.

```
전: - (누락 감소) … 누락이 40건에서 9건으로 감소
    - (누락 특성) … 남은 9건은 전건이 첨부파일 속 내용      ← 9건이 두 번

후: - (누락 감소) 유사어 사전을 적용한 결과 누락이 40건에서 9건으로 크게 줄어
      사전의 효과를 확인하였으며 남은 9건은 색인 대상이 아닌 첨부파일 속 내용
```

합칠 때 **한쪽 사실을 다른 쪽의 근거 자리로 옮기면** 문장이 길어지지 않는다.

---

## 5. 합칠 때는 새로 쓴다

두 항목을 하나로 만들 때 **기존 문장을 잘라 이어 붙이지 않는다.** 무엇을
말해야 하는지 먼저 정하고 문장을 새로 짓는다.

```
붙여넣기:
  - (누락 감소) 유사어 사전을 적용한 결과 총 누락이 기존 40건에서 개선 후
    9건으로 77.5% 감소하여 사전이 실제 누락 감소로 이어짐을 확인하였으며
    잔여 9건은 첨부파일 6건과 이미지 문서 3건 등 전건이 색인 대상 외 문서
                                                    ← 4줄, 접속이 늘어짐
새로 씀:
  - (누락 감소) 유사어 사전을 적용한 결과 누락이 40건에서 9건으로 크게 줄어
    사전의 효과를 확인하였으며 남은 9건은 색인 대상이 아닌 첨부파일 속 내용
```

세부 수치(첨부 6건, 이미지 3건)는 붙임이나 표에서 확인할 수 있으므로 본문에서는
결론만 남긴다. **본문의 층위는 「그래서 무엇을 알았나」다.**

---

## 6. 현황 절은 사실만 쓴다

현황에 판단이나 해법이 섞이면 뒤 절이 할 말을 잃는다.

```
나쁨: 검색 품질을 보완할 필요가 있어 본문 검색 도입을 검토     ← 판단+해법
좋음: 검색은 제목 일치 방식으로 동작하고 있으며 본문 내용은
      검색 대상에 포함되지 않음                               ← 사실
```

특히 **결함을 지적하는 논조와 성능을 높이는 논조를 구분한다.** 기존 시스템을
깎아내리는 서술은 그 시스템을 승인한 사람들에게 보고되는 문서에 맞지 않는다.

| 결함 지적 (피함) | 성능 향상 (권장) |
|---|---|
| 검색 기능이 미흡 | 제목 기준으로 동작하여 개선 여지가 있음 |
| 누락이 반복 발생 | 특정 문서 유형에서 보완 여지가 확인 |
| 품질을 보완할 필요 | 색인 범위를 넓혀 검색 품질을 높이는 방안을 검토 |
