# 양식별 절 구성 상세

## 양식 A — 전형적 보고서

| 순서 | 절 | 쓰는 것 | 분량 기준 |
|---|---|---|---|
| 1 | 제목 | 무엇을 한 결과인지 한 줄 | 1행 |
| 2 | 목차 | 절 제목 나열 | 쪽 하나 또는 상단 블록 |
| 3 | 배경 | 왜 이 일이 시작되었는가 | ㅇ 2~4개 |
| 4 | 목적 | 이 문서가 무엇을 하자는 것인가 | ㅇ 1~2개 |
| 5 | 현황 | 지금 어떤 상태인가 (사실) | ㅇ 2~4개 |
| 6 | 필요성 / 문제점 | 그 상태의 무엇이 문제인가 (판단) | ㅇ N개 |
| 7 | 개선방안 / 추진배경 | 그래서 무엇을 했는가 | ㅇ N개 이상 |
| 8 | 기대효과 | 그 결과 무엇이 좋아지는가 | ㅇ N개 |
| 9 | 향후계획 | 다음에 무엇을 할 것인가 | ㅇ 2~4개 |
| 10 | 붙임 | 근거 자료·상세 데이터 | 별지 |

**현황과 문제점을 나누는 기준**은 사실이냐 판단이냐이다. 「담당자가 개별
접속하여 수작업으로 확인」은 현황이고, 「수작업 확인이라 누락 위험이 있음」은
문제점이다. 현황 절에 판단을 섞으면 문제점 절이 할 말을 잃는다.

## 양식 B — 간소화 보고서

| 순서 | 절 | 묶인 내용 |
|---|---|---|
| 1 | 제목 | |
| 2 | **개요** | 배경 + 목적 |
| 3 | **현황 및 문제점** | 현황 + 필요성/문제점 |
| 4 | **개선방안 / 추진내용** | |
| 5 | **기대효과 및 향후계획** | 기대효과 + 향후계획 (추진내용 절에 녹여도 됨) |
| 6 | 붙임 | |

목차를 넣지 않는다. 개요가 목차 역할까지 겸하므로 **개요를 읽고 전체 그림이
잡히지 않으면 양식 B는 실패한 것이다.**

### 기대효과를 추진내용에 녹이는 방법

절을 따로 두지 않고 각 추진내용 항목의 마지막 하위 항목으로 붙인다.

```
ㅇ (유사어 반영) 검색 기록에서 확인된 누락 표현을 유사어 사전에 반영
  - 부서별 용어를 대표어로 묶어 검색 단계에 적용
  - 누락 40건에서 9건으로 77.5% 감소              ← 기대효과가 여기 붙음
```

이 방식은 항목 수가 적을 때(추진내용 2~3개) 유리하다. 항목이 많으면
기대효과가 흩어져 보이므로 절을 따로 두는 편이 낫다.

## 항목 기호 체계

```
□ 절 제목              HY헤드라인M 16pt
 ㅇ (라벨) 내용         휴먼명조 15pt
  - (라벨) 하위 내용    휴먼명조 15pt
   * 표 아래 단서       함초롬돋움 13pt   (둘째 단서는 **)
```

(2026-09-22 팀장 최종본 기준. 서식 전체는 team-report-hwpx 스킬.)

**추진내용의 `ㅇ` 은 `(라벨)`로 시작하고, `-` 라벨은 한 ㅇ 아래에서 통일한다.**
라벨은 그 항목이 무엇에 관한 것인지 알리는 짧은 말이다. `(목적)`, `(대상)`, `(평가 조건)`, `(품질 검증)`
처럼 쓴다. 라벨이 없으면 읽는 사람은 그 줄이 앞 항목의 연장인지 새 이야기인지
알 수 없다.

**라벨이 떠오르지 않으면 앞 항목에 합친다.** 이름을 붙일 수 없다는 것은
독립된 항목이 아니라 앞 항목의 단서라는 뜻이다. 자세한 판단 기준은
[writing.md](writing.md) 3장 참조.

## 제목 붙이기

제목은 **무엇을 한 결과인지**를 담는다. 수단이 아니라 결과다.

```
좋음: 사내 문서 검색 기능 개선 결과
좋음: 업무 시스템 상시 점검 기능 구축 결과
나쁨: 검색 관련 검토의 건           ← 무엇을 했는지 알 수 없음
```
